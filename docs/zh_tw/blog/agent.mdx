## 被製造出來的「風口」

Agent 開發並沒有想像中那麼多**獨立職缺**。很大一部分熱度，來自培訓班和賣課機構製造的焦慮——先把你嚇住，再煽動你跳進 Agent 賽道。

真到了公司裡，RAG、Agent、LLM 這幾塊，往往讓後端同學花點時間研究，再配一輪 Vibe Coding，就能搓出一個**能演示的 Demo**。門檻並沒有課程宣傳得那麼高——但要分清兩件事：**做出 Demo** 和 **上線可運維、可審計、可規模化**，中間差的是評測、權限、成本、幻覺治理、和存量系統對接，這些往往才是人力大頭。

更準確的說法不是「沒有 Agent 需求」，而是需求在**下沉**：融入現有產品、後端、資料、安全崗位，而不是單獨長出一個巨大的「Agent 開發行業」。

## 產品真相：塞資料，不是造需求

看看市面上的應用：名義上和 AI 結合了，細想一層，多數仍是**把資料塞進去，把結果吐出來**。

於是大量 ToC Agent 創業難做深——這不等於 ToC 完全沒有市場（寫作、修圖、陪伴、通用助手都有先例），而是**多數團隊做的 ToC Agent 沒有護城河、留存差、難形成付費習慣**。企業側也一樣：很多業務並不需要 Agent，頂多做套 RAG、搭個智能客服，需求天花板一眼可見。

智能客服又是高度流程化的活：模型可換、多路召回可配、解析模式可插拔、資料庫可替換，YAML 一寫，開源專案一抄，就能跑起來。標準化會壓縮「純整合、純抄開源」的空間，但企業仍會為**私有化、合規、效果 SLA、行業資料治理**買單——形態會變，不會一夜歸零。

## 高薪幻象：外包、疊要求、與招聘亂象

### 崗位本身

Agent 崗位看起來薪資不低，拆開看，**不少**是外包名義下的包裝（經濟下行週期裡，大廠把正編轉外包並不罕見）。同時也有一些正編在做平台、推理、編排、安全——不能把整條賽道都等同於外包。

要求卻在疊加：既要全端，又要 LLM。可 Agent 編排本身高度模板化，能持續開發的場景並沒有課程裡展示的那么多。Coding Agent、旅遊規劃、醫療規劃——除非你已經在這個行業，或本來就是從業者，否則半路出家往往缺兩樣東西：**領域專業知識**和**營運經驗**。對企業來說，讓現有後端研究、轉崗，往往比外招一個「只會搭 Demo」的人更划算。

### 招聘平台的另一重亂象

和 Agent hype 配套的，還有招聘側的**表演式不匹配**：

- JD 寫得像萬能清單：RAG、微調、Agent 框架、全端、大廠背景、即戰力，薪資區間卻按普通開發給；
- 你按 JD 改履歷，關鍵字對齊、專案描述對口，系統推薦也顯示「匹配度高」；
- 一面沒進，或 HR 直接一句：**「不太合適」**——不給具體原因，或原因與 JD 對不上（要「有從 0 到 1 的 Agent 產品」，你寫了企業內落地；要「懂業務」，你本來就是行業轉碼）。

這不是單純的「你不夠優秀」，而是幾種結構疊加：

1. **崗位未必真招**：掛 JD 收履歷做人才池、應付 headcount、或早已內定，平台只是漏斗入口；
2. **JD 是願望清單，不是篩選標準**：寫的人（HR/業務）和篩的人（HR/用人經理）不是同一套邏輯，履歷匹配演算法看的是詞，人看的是「像不像自己人」；
3. **Agent 崗名大、定義糊**：同叫「Agent 工程師」，一家要調 prompt 做客服，一家要造 IDE，一家要資料標註流水線——履歷符合 A 版 JD，在 B 公司眼裡就是「不合適」；
4. **供過於求後的禮貌拒絕**：「不合適」是成本最低的回覆，比告訴你「預算只夠外包」「我們更想要便宜應屆生」省事。

結果是：**求職者被 JD 訓練著投，HR 被 KPI 訓練著篩，兩邊都在平台上完成儀式，真實匹配反而變少。** 這和賣課製造焦慮是同一套邏輯——外面看起來很熱鬧，你進去才知道門往哪開、鑰匙在誰手裡，沒人告訴你。

## Coding Agent：入場券窄，工程化更深

有人會說：Coding Agent 總該算電腦行業的知識吧？

能進 Claude Code、Codex、Cursor、國內 Trae 這類團隊的人極少；市場上更多的崗位是「用 AI 寫業務」，不是「做 AI IDE」。你拿 Vibe Coding 做出來的玩具專案，很難直接接手**產品級** Coding Agent——那需要的是上下文工程、多檔案編輯、diff、穩定性、企業策略，是團隊級交付，不是「原有 IDE 大牛順手接個 API」就能等價替代。

招一個只會 Vibe Coding、工程素養不足的新人，要補程式理解、補規範，還要防「一鍵生成、直接提交」——給他做 Code Review，有時還不如資深工程師自己用工具來得快。

**更可能改寫行業的人**，是「原工程能力 + 新 AI 能力」的複合體：懂系統、懂業務，再把 LLM 嵌進現有工具鏈；而不是只懂框架、不懂領域的純外行主導。

## 結語

Agent **存在**，但被**過度敘事**了；培訓、JD、平台匹配度，都在放大「你很缺、快上車」的感覺。

少被焦慮帶著跑，多問自己三件事：

1. 我要解決的是真問題，還是「塞資料出結果」的殼？
2. 目標公司是招**落地整合**，還是招**敘事上的 AI 原生**？
3. JD 和履歷「符合」，是否只代表關鍵字過關，不代表崗位真開、標準真清晰？

能回答清楚這些，比多報一門 Agent 課、多投一百份「高度匹配」的履歷，更有用。
